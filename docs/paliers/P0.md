# P0 — Banc d'essai

## But
Disposer d'un banc d'observation fiable avant toute fonctionnalité :
shunt soudé, LED, récepteur BLE sur le PC, protocole de flash écrit.
Le firmware est vide : il ne fait qu'annoncer une ligne en BLE.

## Sections de spec à lire
- Objet et principes
- Matériel (shunt, LED GPIO15, câblage)
- Observabilité (format des logs BLE)
- Protocole de test et de flash

## Fichiers attendus (proposition, à valider au /palier-debut)
- `src/main.cpp` : firmware vide, une ligne BLE toutes les 10 s
- `src/hal/ble/` : émission minimale d'une ligne
- `src/hal/led/` : allumage/extinction, actif bas, env `test` seulement
- `tools/ble-recepteur/` : récepteur PC qui écrit `logs/ble-AAAAMMJJ.log`
- `docs/BANC.md` : câblage du shunt, lecture au multimètre, usage du
  récepteur, rappel du protocole de flash
- `platformio.ini` : build `test` vérifié

## Hors périmètre
Deep sleep, minuteur, accéléromètre, WiFi, NVS, filtre, mode service.
Pas de `go_to_sleep()` à ce palier.

## Test
1. `pio run -e test` sans erreur.
2. Flash selon le protocole (erase, upload, USB débranché, RESET).
3. Récepteur lancé sur le PC pendant au moins 5 min.
4. Lecture du shunt notée (valeur attendue : éveillé, stable).

## Critère de sortie
Le récepteur capte, capteur sur batterie et USB débranché, une ligne
toutes les 10 s, sans trou, pendant toute la durée de l'essai.
Consigné MESURÉ dans DECISIONS.md avec l'env `test` et le commit.

## Question ouverte pour la relecture
La spec ne dit pas si le firmware vide de P0 dort entre deux lignes.
Le sommeil n'arrivant qu'en P1, l'hypothèse retenue est : il reste
éveillé (aucun cycle n'existe encore à fausser). À confirmer.
